Step 2: Iterative prompt refinement

The spec above is the target. Now we encode it into an actual prompt — and the first draft is never the final product.

Lead: BrightLoop Technologies · SaaS · 45 employees · $3.8M revenue · VP of Operations · Austin, TX · Source: webinar signup, downloaded whitepaper on workflow automation, attended live Q&A.

Draft 1 — The vague prompt

System prompt: "You are a sales rep. Look at this lead and tell me if it's good."

What the LLM produced

A generic marketing-style overview. "This lead appears to be quite good." Cited relevant industry, engaged contact, company size looks fine, lead source looks promising. No ICP criteria, no verdict, no reasoning an SDR manager could act on.

Draft 2 — Specific role with ICP criteria

System prompt defined a Senior SDR with explicit ICP criteria (200-2000 employees, SaaS or Fintech, Director-level+, North America) and required a structured verdict with rationale.

Improvement

Clear DISQUALIFIED verdict. Structured evaluation. Right tone. But the model made a factual error — listed Geography as a criteria miss even though Austin, TX is in North America. The output looked like a strong SDR evaluation, but a real SDR manager would catch that error in two seconds.

Draft 3 — Forced step-by-step evaluation

Added one instruction: evaluate each ICP criterion one at a time, state the data from the lead, and determine pass/fail before rendering a verdict.

Result

Geography error disappeared. Model correctly identified Austin, TX as passing North America. Only disqualifying factor: company size at 45 employees, below the 200 minimum. The right call.

No code changed across the three drafts. The Python stayed the same. The model stayed the same. The lead data stayed the same. The only thing that changed was the system prompt — the role definition and instructions.

The skill isn't in writing the code. The skill is in designing the instructions — knowing the role well enough to define it with precision, specifying the criteria, and structuring the output so it's actionable.

Draft 2 — Specific ICP criteria, no step-by-step

Prompt pasted into Claude
You are a Senior SDR at a B2B SaaS company. Your job is to evaluate inbound leads against the following ICP criteria and make a fast qualify/disqualify decision:

- Company size: 200-2,000 employees
- Industry: SaaS or Fintech
- Contact title: Director-level or above
- Geography: North America

For each lead, provide:
1. A one-word verdict: QUALIFIED or DISQUALIFIED
2. ICP criteria met (list which ones)
3. ICP criteria missed (list which ones)
4. A 2-3 sentence rationale written the way you'd explain it to your SDR manager in a pipeline review

Here is the lead:

Company: BrightLoop Technologies
Industry: SaaS
Employee Count: 45
Annual Revenue: $3.8M
Contact Name: Marcus Rivera
Contact Title: VP of Operations
Contact Email: marcus@brightlooptech.com
Location: Austin, TX
Lead Source: Webinar signup
Notes: Downloaded whitepaper on workflow automation. Attended live Q&A.
What to watch for in the output

Much better — structured verdict, right tone. But watch for factual errors. The model may list Geography as a miss even though Austin, TX is in North America. If it does, that's the key lesson: the output looks professional but a real SDR manager would catch the mistake immediately. If it gets geography right this time, the inconsistency itself is the point — "sometimes it works, sometimes it doesn't" is exactly why Draft 3 matters.

Draft 3 — Step-by-step evaluation

Prompt pasted into Claude
You are a Senior SDR at a B2B SaaS company. Your job is to evaluate inbound leads against ICP criteria and make a fast qualify/disqualify decision.

ICP Criteria:
- Company size: 200-2,000 employees
- Industry: SaaS or Fintech
- Contact title: Director-level or above
- Geography: North America (United States, Canada, Mexico)

Instructions:
1. Evaluate each ICP criterion one at a time. For each one, state the data from the lead and whether it passes or fails. Do not skip any.
2. After evaluating all four, give a final verdict: QUALIFIED or DISQUALIFIED.
3. Write a 2-3 sentence rationale the way you'd explain it to your SDR manager in a pipeline review — direct, no fluff.

Here is the lead:

Company: BrightLoop Technologies
Industry: SaaS
Employee Count: 45
Annual Revenue: $3.8M
Contact Name: Marcus Rivera
Contact Title: VP of Operations
Contact Email: marcus@brightlooptech.com
Location: Austin, TX
Lead Source: Webinar signup
Notes: Downloaded whitepaper on workflow automation. Attended live Q&A.
What to watch for in the output

Each ICP criterion evaluated individually with pass/fail. Geography correctly identified as passing. Clear DISQUALIFIED verdict on company size. Actionable rationale. This is what a well-designed role prompt produces — because the step-by-step instruction prevents the model from blending and skipping.

Same lead. Same LLM. Three different prompts. The only thing that changed was how precisely the role was defined and how explicitly the evaluation method was structured.

The skill isn't in the technology. It's in the design of the instructions — knowing the role well enough to define it with precision, specifying the criteria, and structuring the output so it's actionable. That's an operations skill, not an engineering skill.

Technical reference: Python implementation

The same exercise can be run as a Python script using the OpenAI API. The code is identical across all three drafts — only the system prompt changes.

sdr_agent.py
from openai import OpenAI                           # import the library

client = OpenAI(api_key='YOUR_KEY_HERE')              # authenticate with the API

lead = """
Company: BrightLoop Technologies
Industry: SaaS
Employee Count: 45
Annual Revenue: $3.8M
Contact Name: Marcus Rivera
Contact Title: VP of Operations
Contact Email: marcus@brightlooptech.com
Location: Austin, TX
Lead Source: Webinar signup
Notes: Downloaded whitepaper on workflow automation.
"""                                                    # the input data

system_prompt = """Your role-based prompt goes here"""  # swap this for each draft

response = client.chat.completions.create(             # send to the LLM
    model='gpt-4o-mini',                                # which model to use
    messages=[
        {'role': 'system', 'content': system_prompt},  # role instructions
        {'role': 'user', 'content': lead}              # input data
    ]
)

print(response.choices[0].message.content)            # display the output
